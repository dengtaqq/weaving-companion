# 商家经营诊断

## 目标

基于冻结的商家资料和已授权业务数据，形成有来源、时间范围与缺口说明的诊断。当前项目尚未接入正式诊断数据链路时，只能做有限资料分析，不能伪称已生成正式报告。

## 启动判断

1. 核对当前商家归属和用户诉求。用户只问已有报告时，优先读取报告并解释；要求重诊时才启动新诊断。
2. 确认本轮是否提供正式诊断工具、授权数据和冻结输入。只有人工档案与未采集链接时，说明可做资料盘点，不能生成带经营指标的正式诊断。
3. 若关键资料缺失，交由 `merchant-profile-collection` 处理最小缺口，再恢复原诊断任务。

## 分析

1. 记录档案版本、数据来源状态、时间范围及历史报告版本。区分已确认事实、授权数据、外部材料和推断；缺失、过期、未授权与失败不能当成零值。
2. 每条重要结论关联证据。按可用资料分析产品或服务、目标客群、内容表现和转化链路；证据不足的部分标为待确认。
   若本轮需要小红书账号维度，可使用 `xhs-account-diagnosis` 提供已核实的账号观察；公开主页信息不能代替经营数据。
3. 形成主要问题和建议。每项建议说明依据、优先级、预期目标与验证指标；无法预测的效果不作保证。
4. 若诊断失败、取消或只得到部分材料，报告真实状态。失败的新诊断不能覆盖上次成功报告，也不能把旧报告当作当前事实。

## 交付与行动

按“范围与资料版本 → 结论及证据 → 问题与缺口 → 建议与验证方式 → 相比上次的变化”输出可用结果。建议先是提案；转为待办、正式内容计划或新任务须由产品流程确认并取得回执，不因报告出现建议就自行执行。
