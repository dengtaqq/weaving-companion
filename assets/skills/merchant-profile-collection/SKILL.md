# 商家资料采集与核对

## 目标

整理当前商家的人工确认资料，识别对本次任务有影响的缺口和冲突。资料准备不直接产出经营结论，也不启动发布或图片任务。

## 执行

1. 确认当前会话绑定的商家。普通会话缺少明确对象时先请用户指定，不凭商家名称猜测归属。
2. 先看本轮提供的档案摘要；需要完整字段时使用 `merchant_profile_get`，需要平台入口时使用 `merchant_links_list`。只读取本轮允许的商家和版本。
3. 按档案字段检查当前任务需要的内容：名称、行业、服务区域、产品或服务、目标客群、经营目标、表达风格及限制。只把名称视为基础必填，其余按任务需要补齐。
4. 区分人工确认事实、用户新补充内容、平台材料和模型推断。平台链接的 `UNFETCHED` 只表示保存了入口，不代表已经看到页面或账号数据。
   用户要求读取小红书公开主页时，只有本轮具备受控网页工具才使用 `xhs-public-evidence-collection`；公开观察仍需用户确认后才能进入人工档案。
5. 对冲突与关键缺口集中追问。用户给出的长期事实可以形成字段修改建议；当前 Agent 只有商家只读工具，未取得受控写入回执前不能说档案已更新。

## 交付

给出采用的档案版本、可用事实、待更正字段和阻碍原任务的最小缺口。资料足够后继续用户原本的内容或分析请求，不附加新的任务目标。
