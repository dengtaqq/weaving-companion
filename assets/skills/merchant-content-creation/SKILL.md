# 商家内容创作

## 目标

结合商家目标、人工档案和当前请求，生成可审核的文字草稿。内容草稿、正式计划、图片产物和渠道发布是不同结果。

## 执行

1. 明确渠道、推广对象、目标受众、内容形式、素材和限制。已有信息足够时直接创作；只询问影响结果的关键缺项。创作不以先做诊断报告为前提。
2. 商家会话按需读取 `merchant_profile_get`、`merchant_catalog_get` 与 `merchant_links_list`；用户从商品库选定对象时核对条目 ID、版本和已确认卖点。普通会话只使用用户本次提供的材料。未采集链接不能作为内容事实。
3. 从已确认资料提取可说的产品、服务、体验和风格。经营指标、成交效果、客户评价、价格与活动承诺若无可靠来源，不写成确定事实。
   需要新规划小红书选题或安排多篇内容时，按需使用 `xhs-topic-planning`；已有明确主题或半稿时直接沿用。
4. 先确定内容角度与核心信息，再按用户要求交付选题、提纲或完整文案。遵守档案中的表达风格与限制，并标出需要核实或补素材的位置。
   用户要求“类似之前风格”时，先用同会话可见历史和本轮勾选的文字附件提取语气、句长、结构、配色/构图描述等可迁移特征；文字附件按需调用 `list_uploaded_files`、`read_uploaded_text`。本轮勾选的图片仅在 Host 已启用视觉输入且模型实际收到图片时才能作为画面参考。跨会话旧素材若未被本轮提供或正式保存为可读资源，应请用户选入，不假装已读取。
   风格可以借鉴，旧素材中未核实的产品、价格、功效、客户故事不能照搬为新事实。说明参考的文件 ID 或消息出处；图片未成功解析时请用户补文字描述，不猜画面。
5. 修改请求优先针对用户指出的问题调整。长期偏好可建议写入档案，但没有写入回执不能称为已保存。

## 交付

直接给出可阅读的草稿和必要的依据、待核实项。需要图片时可提出视觉需求；只有图片能力已配置且用户明确要求时才进入 `image-creation`。没有 Artifact 登记或渠道回执时，不称为已入库或已发布。
