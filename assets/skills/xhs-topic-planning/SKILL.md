# 小红书选题规划

## 目标

从商家目标、目标人群和可核实的产品服务信息中选出可写、可验证的主题，为文字创作提供清晰输入。

## 执行

1. 明确本轮是单篇选题还是多篇计划。用户已给定主题、素材或半稿时，只判断能否直接写作；不强制重新规划。
2. 商家已确认资料优先。需要避免重复或判断账号方向时，只读取本轮可用的历史内容与账号证据；没有数据时说明无法做历史去重或表现排序。
   关键词库、热点线索、竞品内容线索和商家动态可从本轮冻结的目录索引定位，再按需调用 `merchant_catalog_get`。`USER_PROVIDED_LEAD` 只是待核实线索，不能称为已抓取热点或已比较竞品；有公开证据 ID 才说明实际观察与采集时间。
   工具提供 `merchant_research_get` 且支持 `format` 时，先按需用 `format="REPORT"` 读取本轮已采用研究简报，按 query/itemId 筛选和 offset/limit 分页；旧工具无该参数时按原索引/详情读取。简报的固定五段式保留商家关联、内容角度、限制和证据；未采用的原报告不会自动变成选题依据，过时资料和承接条件仍须复核。
3. 单篇只确定当前主题、目标读者、核心事实、写法和需要的素材。多篇计划再安排主题差异、顺序与覆盖范围；不为凑固定比例编造选题。
4. 公共节日、当地活动、营业安排与商家促销分开核实。日期真实不代表商家一定参与，未确认的优惠和经营决定不能写成已生效。
5. 把用户确认的方向与模型推荐区分。规划完成后作为草稿交给内容创作；没有正式计划保存回执时不称为已排期。

## 输出

交付每个选题的目标人群、主题、核心依据、建议形式、所需素材和待核实项。用户只要方案时在此结束；要求完整内容且能力可用时交给 `merchant-content-creation` 继续。


结尾必须给出用户现在可以执行的下一步，写清推荐选题、需要用户做的一个决定、最少待补事实，以及可直接照填的回复示例（例如“选 T1，目标是拉新，篇幅 500 字，先不写未确认菜品和价格”）。用户已要求“选一条再创作”时，收到含糊的“继续”应集中提示这个选择，不再重复交付一份相似规划；没有选择时不要自行认定方向。没有选题卡保存回执时明确这是聊天文字方案，用户可在当前输入框回复编号或标题；只有真实保存的选题卡才指引点击“研究与选题 → 用此选题创作”。正文生成后再指引“素材与审核 → 保存回复为草稿 → 修改 → 审核下载”；没有成功回执不得称已保存、已审核或已发布。
