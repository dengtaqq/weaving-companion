# 织伴项目亮点源码导读

> 按产品 `master` 当前源码整理。先看调用链，再按简历亮点逐项走读；代码职责以文件中的实际实现为准。

## 整体流程

```text
工作台提交需求
  → Fastify 路由 / SessionService 受理消息
  → 解析模型、Skill、专家与工具配置，生成并保存 Runtime Plan
  → 数据库事务写入用户消息、Run 和首条事件
  → AgentTaskManager 领取 Run，装配上下文并启动 Pi SDK
  → Agent 调用 Host 工具或委派专家，结果与事件写入数据库
  → EventHub 经 SSE 推送；断线后按事件序号补发
  → 文案、审核结果和图片写回图文任务，确认后导出
```

**先走主链路：** [SessionService.acceptMessage](../src/host/modules/sessions/application/session-service.ts) → [db-worker 的 acceptMessage / claimNextRun](../src/host/infrastructure/sqlite/db-worker.ts) → [AgentTaskManager](../src/host/runtime/execution/agent-task-manager.ts) → [PiSdkRuntimeAdapter](../src/host/runtime/adapters/pi/pi-sdk-adapter.ts) → [EventHub](../src/host/http/event-hub.ts)。

图文业务入口在 [publication-routes.ts](../src/host/modules/publication/interfaces/publication-routes.ts) 和 [publication-tool.ts](../src/host/modules/publication/interfaces/publication-tool.ts)：写作接入同一会话 Run；图片由 `GenerationService` 单独排队执行；文案、配图和审核结果回到同一篇图文，再由导出链交付。页面入口见 [content-studio.tsx](../src/renderer/features/publication/content-studio.tsx)。

商家资料页面见 [merchant-page.tsx](../src/renderer/features/merchants/merchant-page.tsx)，Host 端资料路由和基础存储仍有部分位于 [server.ts](../src/host/http/server.ts) 与 [db-worker.ts](../src/host/infrastructure/sqlite/db-worker.ts)。公开采集和选题由 `research` 模块提供：Playwright 采集入口见 [public-page-collector.ts](../src/host/modules/research/infrastructure/public-page-collector.ts) / [xhs-search-collector.ts](../src/host/modules/research/infrastructure/xhs-search-collector.ts)，研究证据与报告落在 [research-store.ts](../src/host/modules/research/infrastructure/research-store.ts)，选题由 [topic-store.ts](../src/host/modules/research/infrastructure/topic-store.ts) 管理。它们为后续创作提供可引用来源和选题，不等同于直接发布内容。

## 简历亮点与源码位置

### 1. 可插拔 Agent Runtime

**阅读顺序：** [capability-registry.ts](../src/host/modules/capabilities/application/capability-registry.ts) → [skill-assets.ts](../src/host/modules/capabilities/infrastructure/skill-assets.ts) → [session-service.ts](../src/host/modules/sessions/application/session-service.ts) → [runtime-plan.ts](../src/host/runtime/execution/runtime-plan.ts) → [pi-sdk-adapter.ts](../src/host/runtime/adapters/pi/pi-sdk-adapter.ts)。

- `resolveCapabilities` 汇合内置与用户配置的 Skill、主 Agent 和专家组；`loadSkillAssets` 读取 Skill 正文及 references，按内容哈希形成快照。模型先看到 Skill 目录，需要时再通过 `read_skill` 读取方法正文。
- `SessionService.acceptMessage` 在受理时解析能力；`createRuntimePlan` 把模型参数、能力版本、工具权限和资料引用写入带哈希的 Plan。排队或恢复执行读取该 Plan，不临时套用新配置。
- Pi 适配层负责会话启动、提示词和受控工具接入。工具超时与重放边界看 [tool-execution.ts](../src/host/runtime/tools/tool-execution.ts) 和 [tool-replay-policy.ts](../src/host/runtime/tools/tool-replay-policy.ts)：区分确定失败与结果未知，未知结果不会被当成成功，也不会默认自动重放。

**怎么理解：** 配置和资产决定“本轮有哪些能力”；Runtime Plan 冻结“本轮实际使用什么”；Pi 适配层负责执行；Host 工具层负责授权和副作用边界。

### 2. 持久任务调度与流式输出

**阅读顺序：** [session-service.ts](../src/host/modules/sessions/application/session-service.ts) `acceptMessage` → [db-worker.ts](../src/host/infrastructure/sqlite/db-worker.ts) `acceptMessage`、`claimNextRun`、`appendEvent` → [agent-task-manager.ts](../src/host/runtime/execution/agent-task-manager.ts) `pollQueuedRuns`、`execute`、`persistRuntimeEvent` → [event-hub.ts](../src/host/http/event-hub.ts) `open`。

- 受理事务原子写入用户消息、Run、冻结 Plan、首条事件和幂等记录；`claimNextRun` 在事务中领取任务，并阻止同一会话并行领取。调度器可同时执行不同会话的 Run。
- `agent_run` 表示一次受理的 Run；每次实际领取递增 `attempt`，运行快照按 Run/Attempt 保存（表结构见 [migrations.ts](../src/host/infrastructure/sqlite/migrations.ts)）。取消请求也写入数据库并沿执行链传递。
- 运行事件先经数据库写入，再交给 `EventHub.publish`；SSE 连接按序号补发历史事件，再接实时事件。前端连接入口在 [client.ts](../src/renderer/api/client.ts) `connectEvents`。
- Host 启动恢复入口见 [main.ts](../src/host/main.ts)：恢复未完成 Run 时结合工具重放策略决定是否继续，不能安全重放的外部副作用保留为失败或待核对状态。

**怎么理解：** DB 负责任务事实和顺序，AgentTaskManager 负责领取与执行，SSE 只是已持久化事件的实时传输层。

### 3. 动态上下文装配与两级压缩

**阅读顺序：** [context-assembler.ts](../src/host/runtime/context/context-assembler.ts) `assembleRunContext` → [task-context-projection.ts](../src/host/runtime/context/task-context-projection.ts) → [pi-sdk-adapter.ts](../src/host/runtime/adapters/pi/pi-sdk-adapter.ts) `compactionExtension`、`planMicrocompact` → [microcompact.ts](../src/host/runtime/history/microcompact.ts)。

- 上下文装配把本轮用户要求、冻结资料、任务快照和可用 Skill 放进模型输入，并按会话、商家和附件归属校验来源。
- 第一层 Microcompact 将可回读的旧只读工具正文替换为带来源的引用；第二层由 Pi SDK 对较早对话生成摘要。摘要指令会纳入当前任务快照，避免压缩时只留下脱离任务的聊天概述。

**怎么理解：** Microcompact 处理工具结果；历史摘要压缩较早对话；任务要求由 Host 单独装配，不依赖摘要记忆。

### 4. 长任务上下文恢复

**阅读顺序：** [task-context-store.ts](../src/host/modules/sessions/infrastructure/task-context-store.ts) → [task-context-projection.ts](../src/host/runtime/context/task-context-projection.ts) → [task-context.ts](../src/shared/task-context.ts) → [run-continuation-store.ts](../src/host/modules/sessions/infrastructure/run-continuation-store.ts)；图文成果关联再看 [text-generation-service.ts](../src/host/modules/publication/application/text-generation-service.ts) 和 [publication-store.ts](../src/host/modules/publication/infrastructure/publication-store.ts)。

- 任务快照保存有效要求、用户原话来源、待处理事项和成果引用；每次推理由 Host 重建任务视图，不把“其他条件不变”交给模型从长聊天里猜。
- 成果引用（`carriers`）定位可继续使用的稿件等产物；近期交互提供当前修改语境。执行续接时组合这些依据，继续处理同一篇内容。

**怎么理解：** 任务快照回答“现在必须遵守什么”，成果引用回答“接着改哪个产物”，近期历史回答“刚刚改了什么”。CarryOn 是组织思路的参考，项目实现以这些本地结构和调用为准。

### 5. 多 Agent 专家编排

**阅读顺序：** [capability-registry.ts](../src/host/modules/capabilities/application/capability-registry.ts) → [assets/experts/merchant-content-team](../assets/experts/merchant-content-team/) → [delegation-service.ts](../src/host/runtime/delegation/delegation-service.ts) → [expert-contracts.ts](../src/host/runtime/delegation/expert-contracts.ts) → [agent-task-manager.ts](../src/host/runtime/execution/agent-task-manager.ts) `executePublicationExpert`。

- 主 Agent 负责理解需求、规划和统筹；当前专家资产包括研究、写作、视觉和审核角色。角色提示词与专家组配置在 `assets/experts/merchant-content-team/`，Skill 在 `assets/skills/`。
- `DelegationService` 为专家建立独立委派上下文并管理提问、调整、取消和提交；`expert-contracts.ts` 按 contract 定义 JSON Schema，并按任务注入 Few-shot 示例，再用 Ajv 校验结构化提交及材料引用。

**怎么理解：** 这是主 Agent 编排多个角色模板，不是每个角色都对应一个固定的独立 Agent 类。选题规划由主 Agent 和相关 Skill 承担，专家角色以当前配置为准。

### 6. AI 图片生成引擎

**阅读顺序：** [image-generation-panel.tsx](../src/renderer/features/publication/image-generation-panel.tsx) → [server.ts](../src/host/http/server.ts) 图片任务路由 → [generation-service.ts](../src/host/modules/media/application/generation-service.ts) → [generation-store.ts](../src/host/modules/media/infrastructure/generation-store.ts) → [image-media-port.ts](../src/host/modules/media/infrastructure/image-media-port.ts) → [image-reconcile-modal.tsx](../src/renderer/features/publication/image-reconcile-modal.tsx)。

- `GenerationService` 领取持久图片任务并调用 Seedream；`generation-store.ts` 管理受理、领取、成功、失败和重启恢复等状态流转，`image-media-port.ts` 处理文生图、参考图改图与返回图片校验。
- 请求键用于幂等受理；服务重启只恢复尚未外发的任务。已外发但结果未知的请求不会自动再发，页面支持人工确认无结果或采用实际生成图片，形成对账记录。

**怎么理解：** 代码通过持久化任务状态实现状态机，不存在单独命名的 `StateMachine` 类；`GenerationService` 是任务编排类。

## 项目收益对应位置

- **创作流程整合：** 从 [content-studio.tsx](../src/renderer/features/publication/content-studio.tsx) 看工作台入口；从 [publication-routes.ts](../src/host/modules/publication/interfaces/publication-routes.ts)、`text-generation-service.ts`、`GenerationService` 顺着看文案与图片如何回到同一图文任务；导出看 [publication-zip.ts](../src/host/modules/publication/infrastructure/publication-zip.ts)。
- **能力扩展与任务续接：** 能力扩展看 `capability-registry.ts` 与资产目录；任务状态看 `agent_run` 和 `runtime_event` 的 DB 操作；要求及成果续接看 `task-context-store.ts` 与 `task-context-projection.ts`。

## 建议的走读顺序

1. 先读本文“整体流程”，再打开 `src/README.md` 的“典型调用链”和“按业务找 Host 代码”。
2. 顺着 `SessionService.acceptMessage → db-worker.acceptMessage → AgentTaskManager.execute` 读一条普通消息，确认受理、冻结、领取和执行边界。
3. 再按面试问题跳转：能力动态装配读亮点 1；任务恢复和 SSE 读亮点 2；长上下文读亮点 3、4；专家协作读亮点 5；图片异常处理读亮点 6。
4. 看每个文件先找文中的函数名，再看它调用的下一层；不要从 `db-worker.ts` 全文件开始读，它还承载其他业务模块的事务操作。
